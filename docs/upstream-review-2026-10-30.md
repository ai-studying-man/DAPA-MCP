DAPA는 업스트림을 패키지로 설치한 포크가 아니라 패턴을 참고해 별도 구현한 서버다. 따라서 `git merge`나 업스트림 파일 일괄 교체로 업데이트하지 않는다. 기존 도구명, 응답 구조, 방위사업청 우선 검색, 현행성 검증을 유지하면서 필요한 동작을 별도 구현한다.

테스트 실행 범위도 `tests/`로 제한했다. 비교용 업스트림 저장소나 중첩 작업 폴더의 테스트를 DAPA 테스트로 잘못 실행하는 문제가 실제로 재현됐기 때문이다. 최신 SDK의 선택적 transport 옵션 타입 변화는 테스트 어댑터에서 처리했다.

## 그대로 유지한 항목

- DAPA는 이미 현재 시행 중인 버전 목록 확인, 정확한 버전의 본문 캐시, 시간 한도, 병렬 조회, 부분 실패 표시, 목록·본문 구분, 원문 기반 답변 제한을 구현했다. 업스트림의 비슷한 기능으로 다시 교체하지 않았다.
- 지식베이스의 DAPA `lstrmAI` 경로는 공식 가이드와 실제 호출에서 정상임을 확인했다. 2026-10-30 강제 조회에서 `방위사업` 검색 19건 중 요청한 2건을 받았다. 업스트림의 일반 법령용어 검색 `lstrm`과 목적이 달라 경로를 바꾸지 않았다.
- `dlytrmRlt`, `lstrmRltJo`, `lsRlt` 등 업스트림에서 수정한 연계 target은 DAPA에 이미 올바르게 등록돼 있다. 잘못된 옛 target으로 되돌리지 않았다.
- 공식 가이드에는 `joRltLstrm`도 존재한다. 업스트림에 해당 도구가 없다는 이유로 DAPA의 경로를 삭제하지 않았다.

공식 계약 확인: [법제처 OPEN API 가이드 목록](https://open.law.go.kr/LSO/openApi/guideList.do).

## 이번에 일괄 도입하지 않은 기능

| 기능 | 판단 |
| --- | --- |
| 업스트림의 21개 결정례 도메인과 기관별 웹 대체 수집 | 국세청·노동·산재 등의 기관별 응답 구조와 원문 보존을 각각 검증해야 한다. 전체 도구 복사는 DAPA의 방위사업 업무 관련성이나 정확성을 보장하지 않는다. |
| 동명 구법 계보, 행정규칙 과거 기준일 조회, 조문별 개정 이력 | 이식 가능하지만 별도의 날짜·법령 ID 계약이 필요하다. DAPA에서 지원하지 않는 과거 조회를 지원한다고 표시하지 않는다. 현재 시행 중인 원문 검증을 유지한다. |
| 판례 제목+본문 검색의 확장 | 방산 직접 관련 판례 누락을 줄일 후속 후보다. 기존 공통 시간 한도와 상위 API 부하를 측정하며 도입해야 한다. |
| 부칙 전용 조회, 장·키워드·페이지 부분 조회 | DAPA의 전체 상세 응답에는 부칙이 이미 포함된다. 전용 선택 인자와 화면 분할은 별도 계약으로 도입할 수 있다. |
| 업스트림 원격 서버 주소와 공유 OC | 도입하지 않는다. 직원의 MCP는 기존 DAPA 운영 주소를 사용하며 법제처 원문은 DAPA 서버가 공식 API로 직접 조회한다. |
| 사용자 입력 기반 자동 OCR | 이번 배포에서 사용하지 않는다. 인식 정확도·처리시간·동시 사용 비용을 별도로 검증해야 한다. |

법령정보는 Git 저장소에 최신 법조문을 복사해야 갱신되는 구조가 아니다. 법령·행정규칙 원문은 법제처 API에서 조회하며, 이번 Git 업데이트는 이를 더 안전하게 조회·해석·전달하는 프로그램의 수정이다.

## 검증 및 배포

- 신규 회귀 테스트를 먼저 실행해 9건의 실패를 확인한 후 수정했다.
- 전체 검사: lint, TypeScript, build, 테스트 251개 통과 / 기존 1개 건너뜀.
- 실제 HWPX 다운로드·파싱, 빈 문서 거부, HTTP/stdio MCP 연결을 기존 통합 테스트로 검증했다. 이 결과를 모든 HWP·PDF 양식의 완전한 보존 보증으로 해석하지 않는다.
- `npm audit`: 전체·운영 의존성 모두 보고된 취약점 0건. 변경 전 전체 보고는 15개 취약 패키지(critical 1, high 8, moderate 6)였다. 감사 데이터베이스 기준이며 모든 보안 위험이 없다는 뜻은 아니다.
- 변경사항은 GitHub main으로 푸시했다. Vercel은 기존 Git 연동을 통해 빌드하며 `/law`, `/mcp`, `/health` 경로와 서울 리전을 유지한다.
- OC는 기존 Vercel `LAW_API_OC`를 사용한다. 별도 클라이언트 OC 입력, 환경변수 공개, 업스트림 공유 서버로의 우회는 필요하지 않다.
